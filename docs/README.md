# Documentation Map

Read the project documentation in this order:

1. [`../README.md`](../README.md) - public commands and six-concept workflow.
2. [`EXPERIMENT_DESIGN.md`](EXPERIMENT_DESIGN.md) - the controlled E&P
   comparison, research questions, and common shock environment.
3. [`RESULTS_AND_QUESTIONS.md`](RESULTS_AND_QUESTIONS.md) - current headline
   findings, numerical summaries, and claim boundaries for every public runner.
4. [`ARTIFACT_SCHEMA.md`](ARTIFACT_SCHEMA.md) - how to read MAT fields, array
   dimensions, units, horizons, provenance, and compact CSV summaries.
5. [`PARAMETER_PROVENANCE.md`](PARAMETER_PROVENANCE.md) - original values,
   active values, and why they differ.
6. [`MODEL_DEVELOPMENT.md`](MODEL_DEVELOPMENT.md) - how the balanced-growth
   New Keynesian rewrite was implemented and how future changes should proceed.
7. [`REPLICATION_LINEAGE.md`](REPLICATION_LINEAGE.md) - where the numerical
   verification history, Git tag `ep-verification-v1`, and frozen replication-
   status document are preserved.
8. [`EE_CONSUMPTION_SPECIFICATION_AUDIT.md`](EE_CONSUMPTION_SPECIFICATION_AUDIT.md)
   - the paper-direct versus released-code EE consumption forecast audit.

Documentation should explain economic intent and the public workflow. Function
headers should explain individual implementation contracts. Generated Dynare
files and exploratory output are not documentation.
